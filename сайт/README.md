# MVP сайт SmailAgent

Демо-прототип на чистом `HTML/CSS/JavaScript` с Python-сервером для загрузки фото и хранения состояния.

## Что реализовано

- Портфолио с фотографиями (`public/portfolio/*.jpg`).
- Онлайн-календарь занятых слотов.
- Регистрация и авторизация клиентов.
- Конструктор программы с выбором аниматоров и расчетом цены.
- Бронирование даты/времени с проверкой занятости.
- Имитация онлайн-оплаты.
- Админ-панель для просмотра и редактирования заказов.
- Авторизация админа (демо): `admin / admin123`.
- Telegram-уведомления при новых бронированиях (через Bot API).

## Как запустить

Из папки проекта (рекомендуется, без Node):

```powershell
python server.py
```

Альтернатива через Node.js:

```powershell
npm install
npm start
```

Откройте:

- Главная: `http://localhost:8080/index.html`
- Портфолио: `http://localhost:8080/portfolio.html`
- Бронирование (календарь + конструктор): `http://localhost:8080/booking.html`
- Детали портфолио: `http://localhost:8080/portfolio-detail.html?type=birthday`
- Админка: `http://localhost:8080/admin.html`

## Настройка Telegram

1. Войдите как `admin`.
2. Откройте `admin.html`.
3. В блоке Telegram укажите:
   - `Bot Token`
   - `Chat ID`
4. После этого новые заказы будут отправляться в Telegram.

## Важно для демо

- Это MVP-прототип без серверной защиты.
- Данные сохраняются в файл `data_store.json` на сервере (в `DATA_DIR`).
- Фото, загруженные из админских форм, сохраняются в `DATA_DIR/portfolio/`.
- Для реального запуска нужен backend + БД + безопасная авторизация.

## Деплой на Render (рекомендуемый быстрый вариант)

1. Загрузите проект в GitHub-репозиторий.
2. На [Render](https://render.com/) создайте `Web Service` из этого репозитория.
3. Укажите настройки:
   - `Runtime`: `Python 3`
   - `Build Command`: пусто
   - `Start Command`: `python server.py`
4. Переменные окружения:
   - `HOST=0.0.0.0`
   - `PORT=10000` (если не задано, Render подставит автоматически)
   - `DATA_DIR=/var/data` (путь к постоянному диску)
5. Создайте и подключите `Persistent Disk` в Render, mount path: `/var/data`.
6. После деплоя откройте выданный URL.
7. Проверьте, что после редеплоя данные не пропадают.
8. Проверьте health-check: `/api/health` должен вернуть `{"ok": true}`.

Важно:
- `server.py` уже умеет читать `PORT` из окружения (нужно для Render/Railway).
- При наличии `DATA_DIR` сайт хранит все изменяемые данные в этой папке.
- При первом запуске сервер копирует стандартные фото из `public/portfolio` в `DATA_DIR/portfolio`.

## Деплой на Railway (альтернатива)

1. Создайте новый проект из GitHub-репозитория.
2. В `Start Command` укажите `python server.py`.
3. Railway автоматически передаст `PORT` в окружение.
4. Добавьте Volume и задайте переменную `DATA_DIR=/data`.
5. Откройте публичный домен проекта после деплоя.

## Что уже подготовлено в проекте

- `render.yaml` — автоконфигурация Render (web service + persistent disk).
- `Procfile` — стандартная команда запуска (`python server.py`).
- `.env.example` — переменные окружения для локального/серверного запуска.
- `.gitignore` — исключены локальные данные и временные файлы.
- `requirements.txt` — файл зависимостей для Python-платформ.
